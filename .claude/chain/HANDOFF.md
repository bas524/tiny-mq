# Event-chain handoff contract (AEF §5.2)

Минимальная событийная цепочка агентов tiny-mq. Каждая стадия по завершении пишет
**машиночитаемый handoff-пакет** — это и есть «готовность входного артефакта» для
следующей стадии. Хук (`Stop` / `SubagentStop`) запускает роутер
`.claude/chain/route.sh`, который по `status` дёргает следующего агента.

Пороги и привязка моделей — [CALIBRATION.md](CALIBRATION.md).

## Куда писать

```
handoffs/<spec>/<stage>.json     напр. handoffs/44/producer.json
handoffs/<spec>/logs/*.log       прогоны, на которые ссылается evidence
handoffs/<spec>/chain.log        журнал роутера (пишет harness, не агент)
```

`<stage>` ∈ `critic` · `producer` · `reviewer` · `perf` · `conformance` · `security` · `docwriter` · `orchestrator`.

## Формат пакета (ядро обязательно — §5.2)

```json
{
  "spec": "44",
  "sdd_ref": "docs/jms-spec/44-message-expiration-sweep.md",
  "stage": "producer",
  "status": "produced",
  "iteration": 1,
  "artifact": "git diff --stat; Consumer.cpp, ConcurrentLinearStorage.{h,cpp}, ...",
  "evidence": [
    "handoffs/44/logs/cpp-verify.log",
    "handoffs/44/logs/bench-recv.log"
  ],
  "evidence_summary": "cpp-verify: 105/105, -Werror clean; perf-check: recv 149->142ns",
  "target_files": ["Consumer.cpp", "Consumer.h", "ConcurrentLinearStorage.h",
                   "ConcurrentLinearStorage.cpp", "tests/ExpirationTest.cpp"],
  "provenance": { "model": "claude-sonnet-5", "role": "Producer", "autonomy": "R2" }
}
```

Обязательное ядро: `spec · status · artifact · evidence · provenance`. Пакет без
ядра роутер считает **не готовым** и ничего не запускает. Это валидация формата границы,
а не блокирующий gate: блокирующие gates стоят только на необратимых рубежах
(Standard 21), а не на каждой передаче.

Стадийные поля сверх ядра: `questions` — только у `critic` (машиночитаемый набор
«что НЕ понял», формат ниже); `question` — только при `status: paused`.

### `evidence` — ссылки, а не проза (Standard 15)

`evidence` — **массив путей к файлам с выводом реальных прогонов**. Текст о прогоне
свидетельством не является: отчёт исполнителя о собственной проверке — это
*заявление*, а не доказательство. Роутер проверяет, что каждый путь существует и
непуст; отсутствующий файл = пакет не готов, следующая стадия не запускается.

Прозаическое резюме кладётся в `evidence_summary` — необязательное поле **без
доказательной силы**. Его нельзя использовать как основание для вердикта; оно
существует только чтобы человек читал пакет глазами.

Отметка «выполнено» без привязанного прогона и незаполненные шаблонные плейсхолдеры
классифицируются как **сфабрикованная проверка** и блокируют переход.

### `target_files` — scope-lock (Standard 18)

Целевой набор файлов сессии, объявленный **до** старта стадии. Изоляция ограничивает,
что агент может сломать снаружи рабочей копии; scope-lock — та же граница внутри неё.

Роутер сверяет `git diff --name-only` с набором. Выход за набор — **остановка
цепочки**, а не предупреждение: граница, о нарушении которой только сообщают,
границей не является. Расхождение пишется в `chain.log`.

Обязательно для стадий с правом изменения (`producer`, `docwriter`). Для read-only
стадий (`critic`, `reviewer`, `perf`, `conformance`, `security`) поле пустое или
отсутствует — и пустой diff у них тоже проверяется: правка кода ревьюером нарушает
Закон 6 и роутер её ловит.

Практический смысл здесь не теоретический: в этом репозитории уже дважды уезжали в
коммит каталоги вне скоупа (`.cache/`, `cmake-build-asan/` — 2613 файлов).

## Значения `status` → маршрут (роутер, §5.1/§5.3)

| status | что делает роутер |
|---|---|
| `criticized` | если вердикт критика «чисто» → запускает **Producer**; иначе **STOP**: спеку правит оркестратор/человек |
| `produced` | запускает **Reviewer** по скиллу `cross-model-review` |
| `rejected` | если `iteration < CHAIN_MAX_ITER` (=5) → возвращает **Producer** на правку (iteration+1); иначе **эскалация человеку** |
| `approved` | reviewer → перф-гейт; специалист → **Doc-writer** (скилл `doc-write`) |
| `paused` | **STOP**: сработали `Stop-conditions` спеки — вопрос `Owner`'у спеки + **подсказка о консультации** (ниже). Не ошибка: работа корректна и **возобновляема** |
| `documented` | **STOP**: рубеж человека/оркестратора (R1) — `milestone-status` + коммит. Не автозапускается (Standard 21) |
| `escalated` | **STOP**: human decision point (§5.3) |
| прочее | **default-deny**: STOP |

`iteration` — счётчик раундов Producer↔Reviewer; Reviewer копирует его из входного
пакета, Producer инкрементирует при правке.

### `paused` ≠ `rejected` ≠ сбой

Три разных исхода, которые нельзя смешивать:

- `rejected` — проверка не пройдена, есть дефект, работу надо **переделать**;
- `paused` — агент столкнулся с неоднозначностью, перечисленной в `Stop-conditions`
  спеки, и остановился вместо выбора молчаливого умолчания. Ошибки нет, сделанное
  корректно, работа **возобновляема** с той же точки;
- сбой агента или инструмента — отдельная категория: возобновление из чек-пойнта,
  запись в `chain.log`.

Смешение «остановлен» и «упал» ведёт к рестарту с нуля вместо возобновления, поэтому
`paused` — отдельный статус, а не частный случай `escalated`.

### Подсказка о консультации на `paused` / `escalated` (§5.2)

Решение на `paused` принимает **`Owner` спеки** (Standard 2) — конкретный человек, не
роль. Роутер читает `Owner` из `sdd_ref` и рядом печатает, с какой ролью ему имеет смысл
свериться по возникшей неоднозначности. Инварианты:

- **адресат — только роль из замкнутой таблицы** Том II §1.2 (Product Owner ·
  Architecture Owner · Engineer · Engineering Team Lead · Information Security Owner ·
  Release Operations Owner · Agentic Platform Owner · Engineering Management). Роли вне
  таблицы подсказка предложить не может; нет подходящей строки — дефект таблицы, не
  повод назвать роль на месте;
- **ключ — стадия × тип артефакта**: стадия из пакета (`stage`), тип — из `target_files`
  / `sdd_ref` / `artifact`. Новых полей в SDD и пакете нет. Локальное соответствие —
  [CALIBRATION.md](CALIBRATION.md);
- **это консультация, а не передача решения**: согласие консультируемого не является
  условием возобновления, иначе воспроизводится координационный слой, который AEF
  предлагает сжимать;
- обращение пишется в `chain.log` событием `CONSULT` (Standard 20): к кому сходили,
  воспроизводимо.

Время между `PAUSED` и возобновлением в `chain.log` — это **время ожидания решения
человека** (контур Flow); порога-цели у него нет, только сдвиг относительно собственной
базовой линии. Снижать его сокращением `Stop-conditions` — анти-паттерн, а не улучшение.

## Что подаётся стадии на вход (Standard 13, ось контекста)

Независимость имеет две оси — **модель и контекст**, и они ловят разные классы
ошибок: смена модели снимает модельную слепую зону, чистый контекст снимает
загрязнение чужим рассуждением.

Поэтому проверяющему (`reviewer`, `perf`, `conformance`, `security`) на вход
подаются **только**:

- `sdd_ref` — спека (критерии приёмки);
- дифф относительно `main`;
- пути из `evidence` — чтобы **перепрогнать**, а не прочитать результат;
- `target_files` — для проверки scope-lock.

**Не подаются** `artifact`-описание и `evidence_summary` производителя: получив
чужой разбор, проверяющий наследует его рамку и перестаёт быть независимым по оси
контекста. Проверяющий обязан прогнать проверки сам (Standard 15).

## Журнал роутера: свидетельство vs заявление (Standard 20)

`chain.log` пишет **harness**, а не агент: время, стадия, статус, модель, команда,
код возврата, пути логов. Это *свидетельство*.

`*.json` пишет о себе сам агент. Это *заявление*: оно дополняет журнал деталями
намерения и принятых решений, но не заменяет его.

**При расхождении приоритет у записи harness**, а само расхождение фиксируется как
отдельное событие (`MISMATCH` в `chain.log`) и разбирается как возможная
сфабрикованная проверка.

### `questions` критика — закрытые множества, ответ в спеку (§5.3)

`critic.json` при `verdict ≠ clean` несёт `questions[]`: `{id, quote, question,
options[…, "other"], answer_goes_to}`. `options` — **закрытое множество** с обязательным
`other`; `answer_goes_to` — секция спеки, куда ляжет ответ. Ответ **возвращается в
спецификацию**, а не остаётся в переписке: следующий раунд ведёт свежий агент, для которого
чат не существует (Закон 1). `questions` непуст при `verdict: clean` — противоречие,
роутер трактует как `needs-work`.

`critic.json` одновременно — запись о разборе критериев приёмки по Standard 3:
`provenance.model` критика ≠ модель producer'а, пакет предшествует коммиту реализации.

## Как запускается цепочка

1. Оркестратор/человек запускает `spec-critic` на спеке → `critic.json`.
   Вердикт «чисто» → Producer; иначе спека возвращается на доработку (правит только
   оркестратор, точечно, только секции из `answer_goes_to`, без попутной переработки).
2. Producer пишет `producer.json` + логи прогонов.
3. Хук ловит завершение → `route.sh` → Reviewer → `reviewer.json`.
4. `approved` → перф-гейт → Doc-writer → `documented` → STOP на рубеже R1
   (человек закрывает спеку); `rejected` → назад к Producer (≤5 раундов).

**Диспатч по умолчанию — dry-run** (роутер печатает команду). Включить реальный запуск:
`CHAIN_EXEC=1` (в `.claude/settings.json` → `env`). Предохранители: маркеры `*.routed`
(не диспатчить повторно), лимит раундов `CHAIN_MAX_ITER`, глобальный потолок
`CHAIN_MAX_DISPATCH`, проверка существования evidence, scope-lock, и **STOP на
approved/paused/escalated** (необратимое — только через человека).
