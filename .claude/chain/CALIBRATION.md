## Пороги

| Что | Стартовое (AEF) | Локально | Основание |
|---|---|---|---|
| Раунды автор ↔ рецензент | 5 | 5 | Сохранён порог предыдущей установки. После него решение принимает Owner. |
| Раунды критика | 5 | 5 | Переносится из кита с учётом оспаривания и сбоя раунда. |
| Потолок переходов | — | 12 на задачу | Предохранитель маршрутизатора. |
| Регрессия горячего пути | по проекту | свыше 5% CPU time/op | Медианы RelWithDebInfo, девять повторов, чередование ABBA, одна машина, baseline main. |
| Независимость | модель и контекст | обе оси | Разные провайдеры, отдельная сессия и собственные проверки рецензента. |
| Дрейф-флаги | < 10, еженедельно | < 5, при закрытии SDD и перед выпуском | Один компонент и нерегулярные выпуски. |
| Трассируемость | 100% на слиянии | 100% для новых SDD и дельт | Источник у каждого ID, пройденные Test:, связь OpenSpec через task_ref. |
| PAUSED → RESUME | диагностическое | без целевого порога | Показывает время решения. |

Проверки после рецензии идут по порядку `nfr`, `conformance`, `security`. Для неприменимой
области специалист указывает N/A и проверяемое основание. Сборка читается из `PROJECT.md`.
Поставка планируется версиями; поддерживаемых релизов пока нет.

## Привязка моделей

`model:` в роли описывает ожидаемую модель, `provenance.model` в пакете отражает фактически
выбранную. В Codex запуск выполняется отдельным процессом. Маршрутизатор печатает команду
с обёрткой из `chain.env`.

| Роли | Модель | Обёртка и провайдер |
|---|---|---|
| analyst, orchestrator, producer, specialist-conformance, doc-writer, platform-agent, knowledge-gardener | `gpt-6.1-sol` | `codex-openai`, встроенный OpenAI |
| spec-critic, reviewer, specialist-nfr, specialist-security | `deepseek-v4-pro` | `codex-deepseek-pro`, профиль `deepseek-pro` |
| explainer | `deepseek-flash` | `codex-deepseek`, профиль `deepseek` |

OpenAI ведёт разбор требования и авторскую стадию. DeepSeek Pro независимо проверяет
намерение, код и отдельные риски. DeepSeek Flash читает результаты для стадии объяснения.
Оба профиля DeepSeek используют прямой `https://api.deepseek.com/`; учётные данные
читаются локальным Codex. При изменении профиля обнови эту таблицу и исполняемую привязку.

## Консультации при остановке

| Стадия или область | Роль | Решение |
|---|---|---|
| analyst, critic, docwriter, explainer | владелец продукта | Граница работы, ожидаемое и принятое поведение. |
| producer, reviewer, conformance | владелец архитектуры | ADR, форматы, объекты, контракты, применимость. |
| nfr | руководитель инженерной команды | Результат горячего пути и остаточный риск. |
| security | владелец информационной безопасности | Секреты, TLS, ACL, вход и десериализация. |
| Сборка и оснастка | владелец агентной платформы | Среда и изоляция исполнения. |

При смене формата, публичного API и инварианта решение заносится в ADR до зависимой
реализации. Риск регрессии записывается в решении с прогонами, выпуск и откат идут
по манифесту, приоритет — по [CONTINUE-HERE](../../tasks/CONTINUE-HERE.md).
