# cross-model-review

При partial собственными прогонами проверь allowed, а по диффу — отсутствие реализации blocked.
Общий файл может содержать обе области. Одного совпадения файлов недостаточно.
В пакете requirement_ids должен точно совпадать с allowed. approved не означает приёмку всей SDD.

Процедура агента-рецензента (контур «Ревью», Стандарт 13). Ключ — **независимость**: ревью выполняется
моделью, отличной от той, что писала код (Закон 6), и агентом с чистым контекстом.

## Две оси независимости (Стандарт 13)

1. **Модель** — снимает модельную слепую зону. Привязка обеих колонок — [CALIBRATION.md](../../chain/CALIBRATION.md),
   и инвариант «автор ≠ рецензент» выполнен по обеим.
2. **Контекст** — снимает загрязнение чужим рассуждением. Рецензент стартует **с пустого контекста**
   и получает только SDD, дифф, `target_files` и пути к логам агента-автора. Разбор и самооценку автора
   он **не получает**.

Обе оси держатся всегда, где есть код: дешевле держать обе, чем классифицировать каждую задачу
(локальное решение — CALIBRATION.md).

## Проверка — это твой прогон (Стандарт 15)

- Собери и прогони тесты сам (`verify`). Логи агента-автора нужны для **сверки**, а не для доверия.
- Расхождение прогона с его логом — блокер **«сфабрикованная проверка»**, отдельным пунктом.
- Симметрично: `rejected` без воспроизведённого дефекта — тоже не проверка. Воспроизведи и приложи лог.
- Твой `evidence` — массив путей к **твоим** логам.

## Перечень проверок ревью

1. **SDD:** каждый сценарий `Test plan` покрыт тестом (`Suite.Case`), и тест реально проверяет семантику.
   Трассируемость (Стандарт 3): `python3 .claude/chain/trace.py tests <SDD> tests` → 0 ошибок, лог в `evidence`.
2. **Объём задачи:** нет изменений «мимо SDD».
3. **Инварианты:** горячие пути → `nfr-gate` без регрессии сверх `регрессия CPU time/op свыше 5% по согласованному набору горячих путей`; унаследованные
   ограничения `см. INHERITED_CONSTRAINTS в PROJECT.md`; парные изменения `кодер ↔ декодер; заголовки ↔ кешированные байты ADR-0008; MessageProperty ↔ PocoAnyVisitor; Destination::save ↔ Destination::deliverCommitted`; повторявшиеся
   дефекты `исключения из деструктора (ADR-0006); регрессия кешированных заголовков (ADR-0008)`.
4. **ADR:** решения из `arch` не нарушены, а изменение инварианта требует нового ADR.
5. **Аудит дрейфа замкнутого мира (Стандарт 5):** новые публичные сущности диффа ↔ `Entity inventory`.
   Это сверка двух множеств. Сущность вне реестра — **дрейф, блокер до MR**. Реестр правит оркестратор.
6. **Целевой набор (Стандарт 18):** дифф внутри `target_files`.

## Вердикт (пакет передачи, Том IV, §5.2)

```
status:   approved | rejected | escalated
evidence: ["handoffs/current/<spec>/logs/reviewer-verify.log", ...]   # пути к ТВОИМ прогонам
artifact: <развёрнутое ревью в docs/reviews/: карта «сценарий → тест», аудит дрейфа, находки>
```

- `approved` — только при полном покрытии и целых инвариантах.
- `rejected` — точное указание нарушенного сценария или инварианта **с воспроизведением**. Не чинить самому.
- **Запрет по умолчанию (§5.3):** после `CHAIN_MAX_ITER` безрезультатных раундов ставится `escalated`. Спорное НЕ вливается.
