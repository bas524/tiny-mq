# adr-write

Контур Knowledge (Standard 8). Значимые технические/архитектурные решения фиксируются как нумерованные ADR в `arch/`, чтобы их можно было пересмотреть осознанно.

## Процедура
1. Следующий номер: посмотри `arch/README.md` (таблица) и файлы `arch/NNNN-*.md`; возьми `max+1`, 4 цифры.
2. Создай `arch/NNNN-краткий-слаг.md` в формате **MADR** (облегчённый), разделы:
   - **Контекст** — что вынудило решение (проблема, унаследованные ограничения);
   - **Варианты** — рассмотренные альтернативы;
   - **Решение** — выбор и почему;
   - **Последствия** — плюсы/минусы, что теперь ограничение для будущих изменений.
3. **Статус** — из словаря репозитория: `proposed` / `accepted` / `superseded by ADR-XXXX` / `deprecated`.
4. Добавь строку в таблицу `arch/README.md` (`| NNNN | Заголовок | Статус |`).

## Когда ADR обязателен
- Отклонение от «унаследованных ограничений» brownfield (стек, форматы, контракты).
- Изменение протокола/кодека, threading-модели (ADR-0005), раскладки таргетов (ADR-0004), формата хранения.
- Обоснованная перф-регрессия (осознанный trade-off) — фиксируется здесь, а не замалчивается.

Пиши по сути и кратко: ADR — это «почему», а не пересказ кода.
