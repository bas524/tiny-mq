# nfr-gate

Шлюз контуров «Качество» и «Верификация». Регрессия — блокер, а не «потом».

## Контролируемые локальные ночные замеры

По решению Owner GitHub Performance отключён, workflow удалён. Сравнительные замеры
горячих путей выполняются локально в согласованное тихое окно по
[M-05](../../../tasks/M-05-local-nightly-performance.md). Там зафиксированы
согласованное расписание, условия запуска и пути к данным.

Обе закреплённые ревизии собираются одним toolchain в Release на одной машине.
Используй `tests/nfr72.py` и `tests/nfr71.py`: ABBA, девять повторов на сторону,
порог регрессии CPU time/op +5%, CPU CV ≤5%. Сохраняй SHA, окружение, affinity,
сырые результаты, CPU median, real time и sample CV; persistent-метрики включают
CPU storage workers. Покрываются все 15 путей, persistent/non-persistent,
обычная отправка и commit. Непригодные серии не становятся pass; ожидание ночного
процесса не должно использовать LLM для повторного опроса.

Независимо проверь SHA сборок и пересчитай медианы и CV по сырым данным.
Сохрани результаты проверки в `handoffs/current/<spec>/logs/`.

**Ограниченный waiver SDD 72 / PR №12:** Owner разрешил «Влить по обычному CI,
perf — отдельная задача». REQ-72-1…8 приняты; REQ-72-9 deferred в M-05,
`performance_verdict=rejected` (run 44475262358, AutoAck +6,59%, CV 0,57% / 1,73%).
Это исключение допуска к выпуску только для 72, не performance pass и не снижение
НФТ-бюджета проекта. Для остальных изменений шлюз сохраняется.

## Локальный прогон

1. **Собери конфигурацию поставки** (не отладочную): `cmake --build --preset release --parallel`.

2. **Прогони замеры производительности**, сохраняя вывод в файл:
   ```
   mkdir -p handoffs/current/<spec>/logs
   ./cmake-build-releasewithdebuginfo/tiny_mq --gbench --benchmark_min_time=1.2s --benchmark_repetitions=9 2>&1 | tee handoffs/current/<spec>/logs/bench-<path>.log
   ```
   Фильтром сузь до затронутого горячего пути.

3. **Сравни с эталоном** (`benchmarks/baseline.md; основная ветка main в соседней рабочей копии`) по `медиане CPU time/op по 9 повторам, ABBA на одной машине`.
   - Эталон меряется в **отдельной рабочей копии** на основной ветке, чередованием ABBA с веткой.
     Два прогона внутри одной ветки стоимость изменения не измеряют: после изменения оба идут по новому коду.
   - При CPU CV >5% серия непригодна; повтори один раз, сохраняя оба результата.
     Сохраняющаяся нестабильность не даёт approved.
   - Оценка по диффу вердиктом не является. Мерь.

4. **Вердикт:**
   - регрессия CPU time/op >5% → технический `rejected`, было/стало, метрика, фильтр;
   - все согласованные пути в бюджете при CPU CV ≤5% → `approved`;
   - отдельный Owner waiver фиксирует основание допуска, сохраняя технический verdict.

## Если замера нет

Изменение горячего пути без замера **не наблюдаемо** → добавь замер до вынесения вердикта.
«Нет замера» ≠ «нет регрессии».

В `evidence` — **пути к логам своих прогонов**. Числа — в `evidence_summary` и отчёт `docs/reviews`;
как свидетельство они не засчитываются (Стандарт 15). Верни рабочее дерево в исходное состояние перед выходом.
