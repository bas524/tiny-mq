# security-review

Шлюз контура «Шлюз безопасности». Область и момент активации:

<!-- project-start -->
сетевой и внешний ввод, credentials, ACL, TLS, десериализация; для остальных изменений явный N/A
<!-- project-end -->

## Область проверки

1. **Аутентификация и авторизация:** права применяются на пути исполнения, а не только в конфигурации.
2. **Секреты:** не в логах, коммитах, конфигурациях по умолчанию, контексте сессии (Стандарт 23).
3. **Внешний ввод:** устойчивость к некорректной длине, усечению, переполнению, безопасные границы.
4. **Ограничение ресурсов:** сдерживание входного потока, лимиты буферов и потоков против злонамеренного клиента.
5. **Деструктивные операции:** за правом и подтверждением.

## Вердикт

```
status:   approved | rejected | N/A
evidence: ["handoffs/current/<spec>/logs/security-*.log"]   # пути к прогонам, не проза (Стандарт 15)
artifact: <что проверено; для N/A — почему изменение области не касается>
```

- `rejected` — конкретная уязвимость и затронутый критерий. Системное решение оформляется ADR.
- Не правь код сам, возвращай задачу агенту-автору.
