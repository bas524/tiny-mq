## ADDED Requirements

### Requirement: Совместимый handshake и кадрирование

Сервер SHALL согласовать STOMP 1.2 и обязательные возможности tiny-mq,
принять раздробленные и объединённые кадры в порядке получения, выполнять
согласованный heartbeat и завершать только затронутое соединение при
ошибке протокола, выходе за лимит или тайм-ауте. Тип дельты — новое
требование текущего узкого среза REQ-73-1, уточняющее исходную SDD 73.
Раздел «STOMP v1 client profile» в design.md принятой редакции
`73-jakarta-broker-transport` задаёт wire-форматы и правила согласования
для сетевого стыка INT-01.

#### Scenario: CapabilityNegotiation

- **WHEN** сырые STOMP 1.2 peers и тестовые peers с расширением tiny-mq
  открывают отдельные loopback-соединения и выполняют матрицу ниже
- **THEN** протокольные результаты, границы кадров, интервалы и состояния
  сокетов совпадают с матрицей. После каждого отказа соседний
  согласованный peer завершает свой сценарий с ожидаемым `receipt-id`
- Test: `WireContractTest.CapabilityNegotiation`

| Проверка | Вход | Обязательное наблюдение |
|---|---|---|
| Стандартный peer | `CONNECT` с LF и `STOMP` с CRLF на разных сокетах, `accept-version:1.1,1.2` и `accept-version:1.2,2.0` соответственно, `host` | `CONNECTED`, `version:1.2` и серверный `heart-beat` на каждом. При `DISCONNECT` с `receipt` приходит соответствующий `RECEIPT`, сокет закрывается |
| Дополнительные заголовки | К валидным CONNECT и STOMP добавить синтетические login, passcode и неизвестные заголовки. В passcode использовать последовательность `p\cq`, буквальную для CONNECT и декодируемую для STOMP. Отдельно подать STOMP с недопустимым escape `\q` в неизвестном заголовке | Оба корректных handshake дают тот же CONNECTED, что без дополнительных заголовков. Неизвестный заголовок с недопустимым escape даёт один канонический ERROR syntax. Значения добавленных заголовков не отражаются в ответах |
| Расширенный peer | Предложены `framing-v1` и неизвестный опциональный токен, требуется `framing-v1`. Во втором соединении предложен только неизвестный опциональный токен | В первом CONNECTED содержит ровно `x-tinymq-capabilities:framing-v1`. Во втором этот заголовок отсутствует. `x-tinymq-required-capabilities` отсутствует в обоих ответах |
| Отказ handshake | Версии без 1.2, отсутствие `accept-version`, присутствующий пустой список версий и формы `1.1,,1.2`, `1.2,`, ` 1.2`, отсутствующий или пустой `host`, неверный `heart-beat`, пустое значение каждого заголовка возможностей по отдельности, неверный список возможностей, неизвестная обязательная возможность либо обязательный токен вне предложения | Без CONNECTED. Несогласованная версия даёт `ERROR version` с заголовком `version:1.2`. Неверная форма списка версий, отсутствующий или пустой `host` и неверный `heart-beat` дают `ERROR syntax`. Неверный список, неподдерживаемый либо отсутствующий в предложении обязательный токен дают `ERROR capability`. Все случаи закрывают сокет после ERROR |
| Фрагментация и склейка | Декодеру подаётся один и тот же поток одним блоком, на каждой границе разреза и байт за байтом. Поток включает CRLF, escapes, повтор заголовка и NUL внутри тела с `content-length`. На сокете одна посылка содержит handshake без receipt и `DISCONNECT` с `receipt`. Повторить с `receipt` только в handshake, задержав первый выход через ScriptedWriter и затем разрешив запись до deadline. Для второго варианта также подать обе команды одним WireBytes настоящему StompConnection до первого WireWritten | Совпадают порядок, поля и байты завершённых кадров, повтор сохраняет первое значение. На сокете `CONNECTED` предшествует `RECEIPT` от DISCONNECT. Если `receipt` есть только в handshake, после CONNECTED приходит только его RECEIPT, затем EOF. Прямой результат содержит только CONNECTED и RECEIPT от handshake, с after_flush и сроком handshake. DISCONNECT не добавляет кадр |
| Остаток после закрытия | На отдельном согласованном StompConnection для каждого варианта подать одним WireBytes DISCONNECT с receipt либо кадр, дающий ERROR syntax. К каждому из двух входов добавить корректный кадр или синтаксически неверные байты. Сроки действуют, бюджет достаточен | Результат во всех случаях совпадает с результатом обработки только завершающего кадра. После DISCONNECT есть один RECEIPT и after_flush, после ошибки один ERROR syntax и after_flush. Хвост не добавляет выход и не меняет срок закрытия |
| Границы и закрытие | Кадр, строка заголовка и число заголовков на лимите и на единицу больше. Неверный терминатор и EOF в незавершённом кадре | Граничные валидные входы приняты. Превышение лимита кадра, строки или числа заголовков даёт один ERROR limit. Неверный терминатор при допустимой длине даёт один ERROR syntax. Drain касается только исходного соединения. Частичный кадр не передаётся. Незавершённый кадр при EOF отбрасывается |
| Heartbeat | Клиент предлагает `20,30`, тестовый сервер `10,40` мс. Повторить с клиентским `020,030`. Отдельно отклонить `20, 30` как syntax. Есть прогоны с трафиком, с отсутствующим заголовком, с нулём в одном направлении и с молчащим peer | CONNECTED содержит строку `heart-beat:10,40` в обоих корректных вариантах, а интервалы в сторону сервера и клиента равны 40 и 30 мс. Исходящий EOL посылается при отсутствии данных. Трафик обновляет входящий срок. Таймеры начинаются после записи конца CONNECTED. При молчании и now >= last_rx + 80 мс ERROR heartbeat-timeout закрывает только это соединение. На точном равенстве принятые в той же итерации октеты предотвращают timeout. Отключённое направление не имеет таймера |
| Незавершённый handshake | Первый кадр ещё не разобран к абсолютному сроку | При `now >= accept + handshake`, даже если доступны новые входные байты, `ERROR handshake-timeout` перед закрытием при достаточном бюджете. Части кадра срок не продлевают |
| CONNECTED не дописан к сроку | Реальный STOMP loopback через production factory, ManualClock и ScriptedWriter. Writer задерживает весь CONNECTED или только хвост, затем часы переводятся на deadline. На отдельных объектах с ненулевыми heartbeat подать последнее WireWritten до срока, ровно на нём и после него | В момент срока закрывается только исходное соединение. Видны ранее записанные октеты, при нулевой записи ответ пуст. Нет хвоста CONNECTED, ERROR или RECEIPT после срока. Из прямых подтверждений только первое даёт keep и запускает heartbeat. На границе и после неё результат immediate, пустой output и nullopt |
| Ошибка с ожидающим CONNECTED | Настоящий StompConnection получает CONNECT, затем до WireWritten отдельным WireBytes получает `DISCONNECT\ninvalid-header\n\n\0` с LF и NUL. Через тот же ScriptedWriter задержать CONNECTED на TCP | Протокол выдаёт ERROR syntax, after_flush и исходный срок handshake. При разрешении записи до срока peer видит ERROR после оставшихся байтов CONNECTED. При задержке до меньшего из сроков handshake и flush транспорт отбрасывает неотправленный остаток и закрывает сокет |

#### Scenario: WireConnectionBoundary

- **WHEN** транспортный владелец обслуживает два независимых объекта
  через общий интерфейс `WireConnection`, подавая байты, монотонное время,
  EOF и ошибку, а узкий независимый test double выдаёт заданные выходные
  байты, срок и запрос закрытия
- **THEN** реальный TCP peer наблюдает точные байты в порядке выдачи.
  Частичная запись, would-block и ошибка детерминированно подаются через
  тестовую точку записи той же транспортной очереди. Курсор продвигается
  только на записанные байты, потери и дубликаты отсутствуют. Ограниченная
  входная порция принимается целиком либо соединение закрывается без
  возврата остатка. Тест сверяет доступный бюджет очереди при двух
  последовательных событиях с незавершённой отправкой и отказ при
  попытке его превысить. События и сроки относятся к своему объекту.
  Реализация создаётся один раз на сокет, закрывается и уничтожается один раз,
  после закрытия вызовов нет. Отказ, переполнение ограниченной очереди
  выхода или истечение срока её сброса закрывают только затронутый сокет,
  соседний объект сохраняет свой журнал, сроки и выход. Настоящий STOMP
  loopback из CapabilityNegotiation проходит тот же интерфейс и остаётся
  обязательным. Двойник проверяет только возбуждение и обработку
  событий общего интерфейса. Проверяются начальный Timer, замена/снятие
  deadline, EOF с незавершённым кадром, read/write failure и остановка
  listener с одним активным объектом и другим в drain. Отдельно повторить
  startLoopback при работающем listener и после stop. Оба вызова дают
  Poco::IllegalStateException. При первом исходный порт и открытое
  соединение продолжают обслуживаться, после stop listener закрыт. Первый получает
  один WireStop, второй не получает новых handle. Очередь drain
  отбрасывается, повторный stop безопасен. Проверяются также null/throw
  factory, throw handle/writer и невалидный результат writer. Повторить
  остановку с активным и draining объектами уничтожением запущенного
  BrokerServer вне потока reactor, без явного stop. К возврату из деструктора
  оба объекта уничтожены. Активный получил один WireStop, draining не
  получил новых вызовов. Клиенты видят закрытие сокетов, listener больше
  не принимает соединения. Reviewer проверяет завершение worker через join.
  Отдельно в override-конструкторе по очереди обнулить factory, clock
  и writer при остальных исправных зависимостях. Каждый конструктор
  выбрасывает Poco::InvalidArgumentException, счётчики вызовов зависимостей равны
  нулю. Защита устаревших notification/generation при повторном
  использовании descriptor подтверждается структурным review. Для stress
  через тот же listener выполнить 256 последовательных коротких подключений.
  В каждом принять и проверить один обмен с двойником, затем закрыть peer.
  Дождаться подтверждённого уничтожения его объекта до следующего accept.
  В логе ровно 256 созданий и 256 уничтожений коротких объектов, без
  обращений к удалённому поколению. Один соседний peer остаётся открытым
  и получает точный ожидаемый ответ до и после серии. Лог отдельно
  отмечает наблюдённый descriptor reuse. После запроса закрытия новых handle нет. Разные подключения
  сохраняют свои часы, буферы и выход. Порция чтения и остаток кадра
  ограничены frame_bytes. В проверке частичной записи сверить выданные и
  записанные октеты с наблюдаемым output_budget. Незаписанный остаток не
  превышает output_bytes. Reviewer по курсору и владению блоками сверяет,
  что хранится только один записанный префикс и завершённые блоки
  освобождаются. Сумма длин живых блоков не превышает двух output_bytes,
  включая префикс. Capacity фиксируется отдельно в memory evidence.
  Формирование выхода учитывает budget до выделения памяти. После 1000 кадров нет
  накопления сохранённого состояния
- Test: `WireContractTest.WireConnectionBoundary`

Строки Test двух функциональных сценариев задают автоматические проверки
наблюдаемого поведения. Структурные проверки с пометкой Reviewer обязательны
для допуска. В `summary` наблюдаемого результата стадии `reviewer` фиксируются
итог и ссылки на код по проверке generation/descriptor reuse, освобождению
и суммарной длине живых блоков, join worker и проверке размера до выделения.
Результат связывается с проверенным SHA. Отсутствие подтверждения по любому
из этих пунктов блокирует приёмку.

#### Scenario: WireBaseline

- **WHEN** на точном SHA успешно пройдены оба функциональных теста REQ-73-1
  и доверенный оператор запускает WireHandshakeProfile на локальной машине
  в согласованное окно по профилю из design
- **THEN** сценарий проходит при наличии девяти повторов на этом SHA.
  Каждый повтор включает 10000 измеряемых сценариев после прогрева,
  завершается с нулём ошибок и содержит конечные CPU/op, throughput,
  p95/p99 и peak RSS. Свидетельство включает SHA, точную команду,
  окружение, разброс метрик и данные по capacity. Отсутствующее или
  неполное свидетельство и любое нарушение условий означают непрохождение.
  Принятый результат становится первым wire-baseline.
