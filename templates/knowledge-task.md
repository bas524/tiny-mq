## Статус и исход — перенос принятой реализации
<!-- Таблица относится только к переносу принятой реализации. Для изменения смысла существующего понятия правило
     «сначала код, потом знание продукта» не применяется: задача меняет модель до реализации, и её MR принимается
     до возобновления работы над кодом. -->

Задача закрывается, когда слито описание, согласованное с действующим кодом. Решение исправить или откатить код
её не закрывает.

| Событие | Что делать |
|---|---|
| MR компонента не слит | ждать, MR знания не сливать |
| код вернули на доработку | обновить продуктовую дельту по окончательно принятой реализации |
| MR компонента окончательно отклонён | закрыть задачу без слияния |
| MR компонента слит | заполнить «Принятая редакция компонента», открыть MR знания. С этого момента идёт известное расхождение |
| MR знания: неверно описание | поправить дельту, открыть MR заново |
| MR знания: принятое поведение не соответствует функции продукта | это дефект после приёмки. Владелец продукта принимает решение «Бизнес-приоритет»: исправить или откатить поведение новой задачей компонента. Если изменение прошло необратимый рубеж, откат невозможен, и дефект разбирается как инцидент. Задача знания ждёт и потом описывает действующий код |

MR знания принимает описание уже принятого поведения, а не само поведение: поведение, видимое пользователю,
принято на рубеже приёмки компонента, до включения.

Перед открытием MR знания: `.claude/chain/kb-task.py check <каталог задачи>` обязан выйти с кодом 0. Он обнаруживает правки
вне набора после записи и не заменяет песочницу.

## Составное намерение
<!-- Только если дельта относится к составному намерению. Одна задача знания на всё намерение. -->

- **Намерение:** `product-kb:<ID>`
- **SDD и принятые редакции компонентов:** `<SDD> → <коммит>`, …
- Сквозной сценарий переносится после слияния всех нужных MR компонентов и зелёного прогона сквозного критерия.
- Исходы оцениваются по всему намерению. Если оно отменено после слияния части компонентных MR, задача знания
  описывает то, что осталось в действующем коде после этого решения. Отмена невлитых задач не закрывает задачу
  знания без слияния описания уже принятых изменений.
