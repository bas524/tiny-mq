# ADR-0002: TCP-транспорт и кадрирование сообщений

- Статус: accepted
- Дата: 2026-05-23

## Контекст

[ADR-0001](0001-wire-protocol-protobuf.md) фиксирует два data plane: STOMP 1.2
(v1) и свой protobuf (v2). Нужен транспорт и схема кадрирования для каждого.
Проект уже линкует `Poco::Net`.

## Решение

- **Транспорт:** TCP. Сервер на асинхронном `Poco::Net::SocketReactor` +
  `SocketAcceptor` (event-driven, не поток-на-соединение) — масштабируется на
  тысячи соединений. Опционально TLS через `Poco::Net::SecureServerSocket`
  (см. `docs/jms-spec/41`).
- **Общий back-end:** оба кодека реализуют единый интерфейс кадров и работают
  поверх одних и тех же `Connection`/`Session` ядра. Выбор кодека — по
  слушающему порту или по первым байтам соединения.

### v1 — STOMP 1.2
- Текстовое кадрирование по спецификации STOMP: команда, заголовки, пустая
  строка, тело, завершающий `NUL` (`\x00`).
- Heartbeats по STOMP (`heart-beat` заголовок при CONNECT).
- Типизированные тела (Bytes/Stream/Map/Object) — через `content-type` +
  существующая сериализация `Message::toBytes()`.

### v2 — protobuf
- Length-prefixed: `[uint32 BE длина тела][тело = сериализованный Envelope]`.
  Лимит размера кадра конфигурируется (по умолчанию 100 MiB), проверяется до
  чтения тела (защита от OOM). Конечный автомат для частичных чтений из сокета.
- `Envelope { uint64 request_id; oneof body { ... } }`; `request_id` для
  корреляции запрос/ответ.
- Heartbeat/Error/FlowControl — отдельные типы в `Envelope`.

## Рассмотренные альтернативы

- **Поток на соединение** (`Poco::Net::TCPServer`) — проще, но не масштабируется;
  допустимо как простой режим клиента.
- **Делимитер-кадрирование для protobuf** — не годится, бинарное тело содержит
  любые байты (для STOMP `NUL`-терминатор корректен, т.к. формат текстовый с
  экранированием).

## Последствия

- Нужен буфер частичного кадра на соединение для обоих кодеков.
- Flow control: в v1 (STOMP) опираемся на TCP back-pressure + in-process
  watermark'и (`docs/jms-spec/42`); в v2 — кредитная схема в `Envelope`.
- Push-доставка вместо pull на серверной стороне consumer'а — см.
  [ADR-0005](0005-session-threading-model.md).
