# ADR-0004: Разделение на CMake-таргеты — core / protocol / server / client

- Статус: accepted
- Дата: 2026-05-23

## Контекст

Сейчас всё (ядро брокера + тесты) собирается в один исполняемый файл `tiny_mq`;
тесты линкуются прямо в него через `ENABLE_TESTS`. С появлением сетевого
протокола, серверной части и отдельной клиентской библиотеки монолитный таргет
перестаёт работать: клиент и сервер должны разделять сгенерированные
proto-типы, но клиентская библиотека не должна тянуть всё ядро брокера.

## Решение

Разнести проект на библиотечные таргеты с явными зависимостями:

- **`tiny_mq_core`** (static lib) — текущее ядро: Exchange, Destination,
  Session, Consumer, Producer, Message-типы, хранилище, Selector,
  TransactionBuffer. Без сети.
- **`tiny_mq_protocol`** (static lib) — сгенерированные из `.proto` типы +
  кодек кадрирования (length-prefix), общий для сервера и клиента. Зависит
  только от protobuf.
- **`tiny_mq_server`** (executable) — сетевой брокер: реактор, приём соединений,
  маппинг protocol ↔ core. Зависит от `core` + `protocol`.
- **`tiny_mq_client`** (static/shared lib) — C++ клиентская библиотека:
  ConnectionFactory/Connection/Session/Producer/Consumer поверх сети. Зависит
  от `protocol` (и от публичных типов сообщений, вынесенных так, чтобы клиент не
  тянул серверное ядро).
- **`tiny_mq_tests`** (executable) — GTest, линкует нужные библиотеки.
  Существующий флаг `ENABLE_TESTS` сохраняется как переключатель сборки тестов.

Публичные типы сообщений (`Message` и наследники, `MessageProperty`) должны быть
доступны и клиенту, и серверу. Выносятся в `core` с аккуратными публичными
заголовками; при необходимости — отдельный `tiny_mq_api` с чистыми интерфейсами.

## Рассмотренные альтернативы

- **Оставить монолит** — отклонено: клиент потянет файловое хранилище и логику
  брокера, размывается граница API.
- **Header-only протокол** — отклонено: кодеген protobuf даёт .cc файлы, нужен
  компилируемый таргет.

## Последствия

- Переписывается `CMakeLists.txt`: вместо одного `add_executable` —
  набор `add_library` + таргеты. Тесты переключаются на линковку библиотек.
- Появляется чёткая граница «что является публичным API клиента».
- Кодоген proto подключается через `protobuf_generate` (CMake) в таргете
  `protocol`.
- vcpkg-манифест дополняется зависимостью `protobuf`.
