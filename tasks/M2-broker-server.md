# M2 — Сетевой брокер (сервер) (P0)

Цель: брокер принимает TCP-соединения, говорит на протоколе M1, отображает
команды на ядро (M0). После M2 брокер можно дёргать сетевым клиентом.
ADR: [0002](../arch/0002-tcp-transport-and-framing.md),
[0005](../arch/0005-session-threading-model.md).

Зависит от: M1 (протокол), M0 (Connection).
Разблокирует: M3 интеграция, M4, M5.

---

## M2-1 (P0) Сетевой акцептор на реакторе
- `Poco::Net::SocketReactor` + `SocketAcceptor`, неблокирующий I/O.
- Парсер кадров (кодек M1-2) на каждое соединение, буфер частичного кадра.
- Acceptance: сервер принимает соединение, читает/пишет кадры эхо-тестом.

## M2-2 (P0) Жизненный цикл соединения ↔ `Connection`
- Каждое TCP-соединение → объект `Connection` (M0-1).
- Обработка `Connect`/`Disconnect`, выдача `clientID`, контроль версии.
- Per-connection сериализация команд (strand) — ADR-0005.
- Acceptance: handshake проходит, некорректная версия отклоняется `Error`.

## M2-3 (P0) Диспетчер команд session/producer/consumer
- Маппинг `CreateSession/CreateProducer/CreateConsumer/Close*` на ядро.
- Хранение соответствия protocol-id ↔ объекты ядра в рамках соединения.
- Acceptance: клиент может создать сессию, producer, consumer по сети.

## M2-4 (P0) Путь отправки (`Send`)
- Десериализация тела в нужный `Message`-подтип, проброс заголовков/properties,
  deliveryMode/priority/ttl, маршрутизация через `Destination`.
- Acceptance: отправленное по сети сообщение попадает в очередь/топик ядра.

## M2-5 (P0) Push-доставка потребителю
- Переход от pull (`Consumer::recv`) к push: брокер сам шлёт `Deliver` в сокет
  при наличии сообщения и готовности потребителя.
- Учёт start/stop соединения (до `start` доставки нет — JMS).
- Acceptance: подписанный по сети consumer получает `Deliver` без явного poll.

## M2-6 (P0) Квитирование и транзакции по сети
- Обработка `Ack` во всех режимах; `Commit`/`Rollback`/`Recover`.
- Корректное взаимодействие с `TransactionBuffer` и хранилищем.
- Acceptance: client-ack, individual-ack и transacted-сценарии проходят по сети.

## M2-7 (P0) Точка входа сервера
- Заполнить `main.cpp` (сейчас пустой каркас): поднять Exchange, реактор,
  загрузить конфиг (`tiny_mq.properties`), graceful shutdown по сигналу.
- Acceptance: `./tiny_mq_server` слушает порт из конфига и завершается чисто.

## M2-8 (P1) Обработка ошибок и изоляция соединений
- Падение/ошибка одного соединения не роняет брокер; ресурсы освобождаются.
- Таймауты на «висящие» handshakes.
- Acceptance: разрыв клиента в любой фазе не течёт ресурсами (проверка в тесте).
