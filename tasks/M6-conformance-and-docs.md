# M6 — Конформанс, бенчмарки, документация (P2)

Цель: доказать соответствие JMS, измерить производительность, оформить
документацию. Финализирует заявленную цель проекта.

Зависит от: M4 (функциональная полнота).

---

## M6-1 (P1) JMS conformance test suite
- Набор тестов, отражающих требования спецификации (`docs/jms-spec`):
  объектная модель, режимы квитирования, транзакции, selectors, durable,
  temporary destinations, request/reply, expiration, priority, noLocal.
- Прогон против сетевого брокера через клиент M3 (не только in-process).
- Acceptance: документированная матрица «требование JMS → тест → статус».

## M6-2 (P2) Интеграционные end-to-end тесты
- Поднятие реального брокера + клиент в CI; многопоточные/многосессионные
  сценарии, рестарт-сценарии (с M5-3).
- Acceptance: e2e-сьют стабильно зелёный в CI.

## M6-3 (P2) Бенчмарки сетевого пути
- Расширить существующий `BenchmarkTest` на сетевой путь: throughput/latency
  для persistent и non-persistent, разные размеры сообщений.
- Acceptance: воспроизводимые цифры, зафиксирован baseline.

## M6-4 (P2) Документация
- Обновить `CLAUDE.md` и `docs/`: архитектура с сетевым слоем, описание
  протокола, руководство по клиентской библиотеке, примеры.
- Сослаться на ADR из `arch/`.
- Acceptance: новый разработчик собирает, запускает брокер и клиент по докам.

## M6-5 (P2) Карта соответствия JMS
- Явная таблица: какие части JMS 2.0 реализованы, частично, не реализованы
  (в т.ч. осознанные исключения вроде ObjectMessage — M0-5).
- Acceptance: таблица в `docs/`, синхронизирована с conformance-сьютом.
