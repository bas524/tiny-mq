# MS-02 — Включить LeakSanitizer в ASan-гейте

**Статус:** ⬜ open · **Приоритет:** средний · **Заведено:** 2026-08-07
**Источник:** ревью спеки 23, раунд 4.

## Суть

ASan-гейт (`.github/workflows/ci.yml`, задание `asan`) запущен с `detect_leaks=0`.

Причина отключения: на Linux ASan включает LeakSanitizer по умолчанию, но вся
верификация «гейт зелёный с первого дня» выполнялась на **arm64 macOS**, где LSan
недоступен в принципе (`detect_leaks is not supported on this platform`). То есть
утечки в этом сьюте **никем и никогда не проверялись**, и включение LSan вместе с
гейтом с высокой вероятностью дало бы красный старт — ровно то, чего гейт должен
избегать: заведомо красный гейт перестают чинить и начинают игнорировать.

## Что сделать

1. Прогнать сьют на Linux с `detect_leaks=1` и посмотреть фактический масштаб.
2. Утечки либо починить, либо (для заведомо живущих до конца процесса объектов)
   внести в файл подавлений с обоснованием по каждой записи. Подавлять «чтобы стало
   зелёно» без разбора нельзя.
3. Убрать `detect_leaks=0` из задания и обновить комментарий.

## Критерий готовности

`ASAN_OPTIONS=detect_stack_use_after_return=1` (без `detect_leaks=0`) — сьют зелёный
на ubuntu-latest.

## Почему это стоит сделать

Класс «объект не освобождён» ортогонален use-after-free, который гейт уже ловит.
На спеке 23 ASan нашёл пять дефектов памяти, два из которых оказались давними и не
связанными с текущей работой. Оснований считать, что с утечками картина лучше, нет.
